## Part 1 of 1

Major, app/controllers/extended_api_issue_histories_controller.rb:212
The code trusts a prior token check and then unconditionally dereferences the attachment returned by Attachment.find_by_token inside attach_extended_api_history_files. Because the initial validation and the update are not atomic, a concurrent request can consume the same upload token between the validation (extended_api_history_attachment_errors) and the update, making find_by_token return nil at attach time. That leads to a NoMethodError (undefined method update_columns for nil:NilClass) and a 500, despite the contract promising 422 and “nothing stored.”

Concrete failure scenario:
- Two concurrent admin requests A and B submit the same token T in attachments for different issues.
- Both pass extended_api_history_attachment_errors (token valid at that moment).
- A reaches attach_extended_api_history_files first and attaches T.
- B then calls Attachment.find_by_token(T), which returns nil (token already used) and B crashes on attachment.update_columns, returning 500 after rolling back the transaction.

Fix:
- Make the attachment update robust to this race and return 422, without writing anything:
  - Re-check the token inside the transaction and perform a conditional update that only succeeds if the row is still unattached (container_id and container_type are NULL).
  - If the conditional update affects 0 rows, abort the transaction and return “Token is invalid”.
  - Keep using the filename sanitizer via the model’s setter, but pass the sanitized value into the conditional update.

Example patch sketch:
- Define a small sentinel to signal the race:
  class TokenAlreadyUsed < StandardError; end

- In create:
  begin
    Journal.transaction do
      journal_ids = insert_extended_api_history_journals(journals)
      attachment_ids = attach_extended_api_history_files(attachments) # may raise TokenAlreadyUsed
    end
  rescue TokenAlreadyUsed
    return render_api_error_message([extended_api_history_invalid(:token)])
  end

- In attach_extended_api_history_files:
  attachments.map do |given|
    att = Attachment.find_by_token(given[:token])
    raise TokenAlreadyUsed unless att
    cols = {
      container_id: @issue.id,
      container_type: 'Issue',
      author_id: given[:author_id].to_i,
      created_on: parse_extended_api_time(given[:created_on])
    }
    if given[:filename].present?
      att.filename = given[:filename].to_s
      cols[:filename] = att.filename
    end
    cols[:content_type] = given[:content_type].to_s if given[:content_type].present?
    cols[:description] = given[:description].to_s if given.key?(:description)

    # Conditional, race-proof attach
    updated = Attachment.where(id: att.id, container_id: nil, container_type: nil).update_all(cols)
    raise TokenAlreadyUsed unless updated == 1

    att.id
  end

Resolution: fixed in the next commit, with a test that fails without it (500 before, 422 after): the attachment is updated with a conditional update_all (only while container_id is NULL); 0 rows or a token no longer found raises inside the transaction, which rolls back the journals, and the answer is 422 "Token is invalid". The realistic path is the same token twice in one request (test test_history_with_the_same_upload_twice_is_refused_and_stores_nothing); two concurrent requests take the same branch.
