Blocker, lib/redmine_extended_api/custom_fields/attribute_policy.rb:83-90
Problem: enumeration_format? and enumeration_format_object? use is_a? on a FieldFormat class object. Redmine::FieldFormat.find returns a class, and CustomField#format also returns a class, not an instance. In Ruby, a class object is not is_a? a superclass module/class; the correct check is subclass comparison (<=). As a result, enumeration_format? always returns false, so:
- AttributePolicy will never expose :enumerations.
- enumerations_from_params will never process the enumerations payload (it returns []), breaking SD-18 for core “enumeration” and any format built on EnumerationFormat.
Concrete failure scenario:
- POST /extended_api/custom_fields.json with type IssueCustomField, custom_field: { name: "Enum", field_format: "enumeration", enumerations: [{name: "Alpha"}, {name: "Beta"}] } by admin.
- Expected: field created with two options Alpha, Beta.
- Actual: options ignored; field has no enumerations; response JSON also lacks the options.
Fix: Compare using subclass semantics.
- def self.enumeration_format?(field_format)
-   enumeration_format_object?(Redmine::FieldFormat.find(field_format.to_s)) if defined?(Redmine::FieldFormat)
- end
+ def self.enumeration_format?(field_format)
+   fmt = defined?(Redmine::FieldFormat) ? Redmine::FieldFormat.find(field_format.to_s) : nil
+   enumeration_format_class?(fmt)
+ end
- def self.enumeration_format_object?(format)
-   defined?(Redmine::FieldFormat::EnumerationFormat) ? format.is_a?(Redmine::FieldFormat::EnumerationFormat) : false
- end
+ def self.enumeration_format_class?(format_class)
+   defined?(Redmine::FieldFormat::EnumerationFormat) && format_class.respond_to?(:<=) &&
+     (format_class <= Redmine::FieldFormat::EnumerationFormat)
+ end
And update enumerations_supported? to use enumeration_format_class?(format).

Resolution: not a defect. `Redmine::FieldFormat.add` stores `klass.instance` (core `lib/redmine/field_format.rb:24-26` on 7.0, the same on 5.1 and 6.1), so `find` and `CustomField#format` return the singleton instance, not the class: measured on 7.0, `Redmine::FieldFormat.find("enumeration").class` is `Redmine::FieldFormat::EnumerationFormat` and `is_a?` is true. The SD-18 tests (core `enumeration`, a subclass format, `depending_enumeration`) and the live probes (201 `["Alpha","Beta"]`) pass; `Class <= ...` would be false for an instance and break it. Not changed.
