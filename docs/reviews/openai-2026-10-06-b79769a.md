  File: lib/redmine_extended_api/patches/api_helpers.rb: around render_api_error_message
  Problem: The render call uses an unknown option key "format: [:api]" instead of "formats: [:api]" (or none at all inside format.api). In Rails 7/8, render does not accept a "format" keyword; while being inside format.api usually makes this work implicitly, passing an unknown option may be ignored now but risks raising ArgumentError/ActionView::MissingTemplate under different Rails versions or middleware stacks.
  Scenario: An API client hits an endpoint that calls render_api_error_message (e.g., invalid custom field type, invalid overrides). On some Rails setups, render(template: ..., format: [:api], ...) is treated as an unknown option and can raise, returning 500 instead of the intended 422 with an error body.
  Fix: Remove the explicit format option or use the correct key. For example:
    format.api do
      @error_messages = Array(message)
      render template: 'common/error_messages', status: status, layout: nil
    end
    or, if you really want to force it, render template: 'common/error_messages', formats: [:api], status: status, layout: nil
  Resolution: not changed. `format: [:api]` is exactly what core's ApplicationController#render_api_errors passes (7.0-stable-GEOxyz app/controllers/application_controller.rb:793, also in 5.1); the integration tests render this path in JSON and XML on 7.0 and 5.1 with 422 and a body.
