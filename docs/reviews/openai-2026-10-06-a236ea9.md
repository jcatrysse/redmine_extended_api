Major, lib/redmine_extended_api/patches/api_helpers.rb:75-83
render_api_error_message renders with render template: 'common/error_messages', format: [:api]. The render option key is formats (plural) in Rails; using format is ignored. Depending on the responder, this can select the wrong template or raise Missing template (e.g. a JSON API request hits format.api and then tries to render common/error_messages without the api format enforced), yielding an HTML page or a 500 instead of the JSON/XML error list.
Failure scenario: POST /extended_api/custom_fields.json with an invalid or missing type under Redmine 7 returns 500 Missing template common/error_messages, or an HTML page, instead of a 422 JSON with {"errors":["Type is invalid"]}.
Fix: replace format: [:api] with formats: [:api], mirroring core’s render_api_errors implementation:
format.api do
  @error_messages = Array(message)
  render template: 'common/error_messages', formats: [:api], status: status, layout: nil
end
